Observer (观察者) 负责将数据对象的所有属性转换为 getter/setter，实现数据劫持。递归遍历对象，深度监听。
Dep (依赖收集器) 每个响应式属性都有一个对应的 Dep 实例。它负责收集依赖（Watcher）并在数据变化时通知它们。
Watcher (订阅者) 代表一个依赖（如组件渲染函数、computed、watch）。当数据变化时，Dep 通知 Watcher，Watcher 执行回调更新视图。

Vue 3 响应式原理 (Proxy)

Vue 3 使用 ES6 的 Proxy 进行代理，配合 Reflect 操作对象。核心是 reactive (Proxy)、effect (副作用) 和 track/trigger (依赖管理)。

Reactive (Proxy) 使用 Proxy 代理整个对象，拦截 get、set、deleteProperty 等操作。无需递归初始化，懒代理。
Effect (副作用) 响应式系统中的执行单元（类似 Vue 2 的 Watcher）。当依赖的数据变化时，effect 会重新执行。

trigger: 在 set 中查找并执行相关的 effects。

先认识两个原生 API：Object.defineProperty 与 Proxy

两个都是 JavaScript 语言本身提供的「对象拦截」能力，Vue 只是使用者。 先看 API 本身，后面的对比和原理就都通了。

1. Object.defineProperty：属性级拦截（ES5）

作用是给「某一个属性」定义描述符。Vue 2 用的是访问器描述符 （get / set），即把属性变成 getter/setter。

基本用法
const obj = {}
let val = 1
Object.defineProperty(obj, 'a', {
  enumerable: true,    // 可枚举
  configurable: true,  // 可配置（能否 delete / 重新定义）
  get() {              // 读取 obj.a 时触发
    console.log('get a')
    return val
  },
  set(newVal) {        // 给 obj.a 赋值时触发
    console.log('set a =', newVal)
    val = newVal
  }
})

obj.a = 2        // ✅ 触发 set
console.log(obj.a) // ✅ 触发 get
它做不到的事（Vue 2 硬伤的根源）
const obj = { a: 1 }
// 假设 a 已经被 defineProperty 劫持...

obj.b = 3        // ❌ 无法拦截：b 从未被 defineProperty 定义过
delete obj.a     // ❌ 无法拦截：没有对应钩子

const arr = [1, 2, 3]
arr.length = 0   // ❌ length 是 non-configurable，根本无法 defineProperty
arr[3] = 4       // ❌ 新下标无法被预先 defineProperty

// → 所以 Vue 2 只能：增删用 Vue.set/Vue.delete（手动通知）
//                 数组重写 push/pop/shift/unshift/splice/sort/reverse 七个方法
核心局限 defineProperty 必须针对「已知的 key」逐个定义， 且语言层面只提供 get/set 两个钩子 —— 它天生不知道 「对象多了/少了一个属性」这种事件。这是 API 设计决定的，不是 Vue 能绕开的。

2. Proxy：对象级代理（ES6）

作用是给「整个对象」包一层代理，之后对代理对象的任何操作 都会先经过你定义的 handler（trap 集合）。

基本用法
const raw = { a: 1 }
const proxy = new Proxy(raw, {
  get(target, key, receiver) {
    console.log('get', key)
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    console.log('set', key, '=', value) // 新增属性也会进来！
    return Reflect.set(target, key, value, receiver)
  },
  deleteProperty(target, key) {
    console.log('delete', key)
    return Reflect.deleteProperty(target, key)
  }
})

proxy.a = 2       // set a = 2
proxy.b = 3       // ✅ set b = 3（新增！defineProperty 做不到）
delete proxy.a    // ✅ delete a

// 数组同理（数组也是对象）
const arrP = new Proxy([1, 2, 3], { /* 同上 handler */ })
arrP[0] = 9       // ✅ 拦截到下标赋值
arrP.push(4)      // ✅ push 底层就是「读 length + 写下标」
arrP.length = 0   // ✅ length 也能拦
13 种 Trap get / set / has（in）/ deleteProperty / ownKeys（for…in、Object.keys）/ getOwnPropertyDescriptor / defineProperty / preventExtensions / getPrototypeOf / setPrototypeOf / isExtensible / apply / construct
本质区别 defineProperty 拦的是「某个属性」；Proxy 拦的是「对这个对象的操作」。 属性存不存在、是不是数组、是不是 Map/Set 都无所谓。
Reflect 的角色 Vue 3 在每个 trap 里都用 Reflect.xxx(target, key, receiver) 执行默认行为，保证 this 指向正确（getter 里用 this.xxx 时仍走代理），否则深层响应式会断。

Proxy 是如何实现那些「方便特性」的？

「增删属性自动监听」「数组方法自动监听」「子对象懒代理」都不是 Proxy 白送的， 而是 Vue 3 在 trap 里做的二次加工。逐个拆开看。

1. 增删属性：set / deleteProperty 对「不存在的 key」照样触发

因为 Proxy 拦的是「操作」而非「属性」，obj.newKey = 1 也走 set trap。 Vue 3 在 set 里用 hasOwn 判断是新增还是修改，触发不同类型的 trigger；删除则走 deleteProperty trap。

Vue 3 baseHandlers 的 set 简化版
function createSetter() {
  return function set(target, key, value, receiver) {
    const hadKey = hasOwn(target, key) // 判断是「新增」还是「修改」
    const result = Reflect.set(target, key, value, receiver)
    if (!hadKey) {
      trigger(target, TriggerOpTypes.ADD, key, value)   // ✅ 新增属性
    } else if (hasChanged(value, oldValue)) {
      trigger(target, TriggerOpTypes.SET, key, value)   // 修改属性
    }
    return result
  }
}
// deleteProperty trap 里：trigger(target, TriggerOpTypes.DELETE, key) ✅
关键点：ITERATE_KEY for...in / Object.keys 走的是 ownKeys trap， 收集的依赖挂在特殊的 ITERATE_KEY 上。新增 / 删除属性时 Vue 3 会连 ITERATE_KEY 的依赖一起通知 —— 所以 v-for 渲染的列表也能感知到「多了/少了一项」。

2. 数组：方法调用本质就是「对象操作」

JS 里数组就是特殊对象，所以 arr.push(x) ≈ arr[arr.length] = x，arr.includes(x) 是先 get 到方法再调用 —— 全部落进 get/set trap。不需要重写任何数组方法。

数组操作 → trap 的映射
const arr = reactive([1, 2, 3])

arr[0] = 9         // set trap：下标赋值
arr.length = 0     // set trap：改 length
arr.push(4)        // get trap（length、push）+ set trap（写入新下标）
arr.includes(2)    // get trap（读 includes 方法）+ 循环里逐个 get
delete arr[0]      // deleteProperty trap
Vue 3 的细节处理 push 会触发「读 length + 读方法 + 写 length + 写下标」多次 trap， Vue 3 在 get trap 里对数组的 push/pop/shift/unshift/splice 做了 pauseTracking / resumeTracking 包裹，避免重复 track 导致的死循环与多余依赖 —— 这是 Proxy 方案需要的「收尾补丁」。

3. 子对象懒代理：Proxy 本身是「浅」的，Vue 3 在 get 里补

很多人以为 Proxy 天生深层响应式，其实 new Proxy(obj, handler) 只代理第一层：proxy.child 通过 get 拿到的是 原始对象。Vue 3 的做法是：get 返回值前判断，是对象就再包一层 reactive() —— 于是「访问到哪一层，哪一层才被代理」。

Vue 3 baseHandlers 的 get 简化版
function createGetter(isReadonly = false, shallow = false) {
  return function get(target, key, receiver) {
    const res = Reflect.get(target, key, receiver)
    track(target, TrackOpTypes.GET, key)   // 依赖收集

    if (isRef(res)) return res.value
    if (isObject(res)) {
      // ✅ 关键：返回前把子对象转成响应式（只有访问到才发生）
      return isReadonly ? readonly(res) : reactive(res)
    }
    return res
  }
}
对比 Vue 2 Vue 2 必须初始化时就把整棵数据树递归 observe 一遍（eager）；Vue 3 是用到才代理（lazy）。 这就是 Vue 3 初始化更快、且「没被用到的子对象永远不浪费性能」的根本原因。

Vue 2 Object.defineProperty vs Vue 3 Proxy（基础响应式手段）

Vue 2 和 Vue 3 的「响应式」本质都是拦截对数据的读写并通知更新， 差别在于用什么手段拦截：

  • Vue 2（ES5）：在初始化时递归遍历 data 的每个属性， 用 Object.defineProperty 给每个 key 单独挂 getter/setter —— 只能拦截「读取」和「赋值」两种操作。
  • Vue 3（ES6）：在初始化时只给整个对象包一层 Proxy，拦截对该对象的所有操作 （get / set / deleteProperty / has / ownKeys …），无需遍历属性，且子对象懒代理。

对比维度 Vue 2 · Object.defineProperty Vue 3 · Proxy
劫持粒度 逐属性：每个 key 单独 defineProperty 整个对象：一个 Proxy 包住即可
能拦截的操作 仅 get / set（赋值） 13+ 种：get / set / deleteProperty / has / ownKeys / in …
新增属性 ❌ 监听不到，需 Vue.set ✅ 自动（deleteProperty + ITERATE_KEY 触发）
删除属性 ❌ 需 Vue.delete ✅ 自动（deleteProperty）
数组 ❌ 下标 / length 监听不到，需重写 7 个数组方法 ✅ 原生支持下标、length、push 等
初始化性能 递归遍历全对象（一次性 eager），大对象有开销 懒代理（访问到才代理子对象），启动更快
Map / Set / WeakMap ❌ 不支持 ✅ 通过 collection handlers 支持
基本类型 data 整体必须是对象 reactive 也只能对象；但 ref 解决基本类型
浏览器兼容 ES5，IE9+ Proxy，现代浏览器（不支持 IE）
Vue 2 的硬伤 监听不到「新增 / 删除属性」与「数组下标 / length」，所以必须 Vue.set / 重写数组方法；且初始化要递归遍历全部属性，深层大对象有性能损耗。
Vue 3 的优势 原生支持增删、数组、Map/Set；懒代理让启动更快；依赖管理收敛成一套 track / trigger / targetMap，代码更简洁、可维护性更好。
代价 Proxy 无法被 polyfill，这是 Vue 3 彻底放弃 IE 的根本原因。
为什么 Vue 3 要从 defineProperty 切换到 Proxy？ 核心诉求是「真正完整的响应式」：新增 / 删除属性、数组下标修改、 Map/Set 这些在 Vue 2 里要么做不到、要么要 hack（重写数组方法、Vue.set）， 而 Proxy 在语言层面一次性解决。再叠加懒代理带来的初始化性能提升，迁移收益明显大于兼容 IE 的代价。

Vue 2 核心实现代码 (手写最简版)

下面用不到 60 行代码还原 Vue 2 响应式「三件套」：Dep （依赖收集器）、defineReactive/observe （数据劫持）、Watcher（订阅者）。

1. Dep：每个响应式属性对应一个依赖收集器
class Dep {
  constructor() {
    this.subs = [];          // 存放依赖当前属性的 Watcher
  }
  depend() {
    if (Dep.target) this.subs.push(Dep.target); // 收集正在计算的 Watcher
  }
  notify() {
    this.subs.forEach(w => w.update());         // 通知所有 Watcher 更新
  }
}
Dep.target = null;            // 全局标记：当前正在执行的 Watcher
2. 数据劫持：Object.defineProperty 递归定义 getter/setter
function defineReactive(obj, key, val) {
  const dep = new Dep();
  if (typeof val === 'object' && val !== null) observe(val); // 递归子对象
  Object.defineProperty(obj, key, {
    get() {
      dep.depend();          // 读取时收集依赖
      return val;
    },
    set(newVal) {
      if (newVal === val) return;
      val = newVal;
      dep.notify();          // 写入时派发更新
    }
  });
}

function observe(obj) {
  if (typeof obj !== 'object' || obj === null) return;
  Object.keys(obj).forEach(key => defineReactive(obj, key, obj[key]));
}
3. Watcher：订阅者（组件渲染 / computed / watch 的抽象）
class Watcher {
  constructor(getter) {
    this.getter = getter;
    this.value = this.get();
  }
  get() {
    Dep.target = this;       // 标记自己，get 触发时才能被收集
    const value = this.getter();
    Dep.target = null;       // 收集完置空
    return value;
  }
  update() {
    console.log('[update] 新值:', this.get());
  }
}
4. 跑起来看效果
const data = { name: 'Vue2', count: 0 };
observe(data);
new Watcher(() => data.count); // 读取一次 → 建立依赖
data.count = 1;                // 触发 setter → notify → update()
// 输出：[update] 新值: 1

Vue 2：核心代码 ↔ 单文件组件（Options API）

上面那段不到 60 行的代码只有三个「积木」：observe/defineReactive （把数据变成响应式）、Dep（每个属性一个依赖盒子）、Watcher （订阅者）。在真实的单文件组件里，Vue 在 new Vue() 的初始化阶段（initState / $mount）把这些积木和你在 Options API 里写的配置一一接上。关系如下：

你写的 (Options API) 底层对应 怎么起作用的
data() { return {...} } observe() + defineReactive() data 返回的对象被递归遍历，每个 key 挂上 getter/setter，并闭包持有一个 Dep。这就是「响应式状态」的本体。
template / render 渲染 Watcher（Render Watcher） 模板被编译成 render 函数，作为「渲染 watcher」的 getter。首次执行 render 时读到的 data 属性，会把这个渲染 watcher 收进各自的 Dep；之后任一属性变化 → notify() → watcher 更新 → 重渲染。
computed: { full() { return this.a + this.b } } 计算属性 Watcher（lazy） 每个 computed 是一个懒 + 带缓存(dirty) 的 watcher。它内部读到的 this.a / this.b 会把 computed watcher 收进它们的 Dep；而读取 computed 的地方（如 render）又会把 computed watcher 收进自己的依赖。只有依赖变了才重算。
watch: { x(v) {} } 用户 Watcher（User Watcher） 每个 watch 项生成一个 user watcher，getter 是监听的表达式/函数，变化后调用你的回调 (newVal, oldVal)。
methods: { ... } 普通函数，非响应式 方法只是绑定到实例的普通函数，本身不产生 Watcher。在 render 期间调用方法时，方法里读到的响应式数据会「顺带」 参与依赖收集（此时 Dep.target 是渲染 watcher）。
props 同样是响应式（defineReactive） props 也被劫持，可以作为依赖被任意 watcher 收集。
渲染 Watcher 每个组件一个，getter = render 函数。负责把「模板用到的数据」和「这个组件」绑定起来； 数据变 → update() → 进入异步更新队列（nextTick 批量 flush，去重避免重复渲染）。
计算 Watcher (computed) lazy + dirty 缓存：没被读取时不求值；读取且 dirty 才重算； 依赖变化只把 dirty 置 true 并通知「读了它的上层」重新取值。
用户 Watcher (watch) 对应 watch 选项；变化后执行你传入的回调，并带上新旧值。

一个完整流程（以改 data 为例）：

1. new Vue() → initState → observe(data)：data 每个属性挂上 getter/setter 和 Dep。

2. $mount → 创建渲染 watcher，执行 render 函数。

3. render 读 this.message → 触发 getter → dep.depend() 把「当前 Dep.target（渲染 watcher）」收进 message 的 Dep。

4. 用户改 this.message = 'hi' → 触发 setter → dep.notify() → 渲染 watcher 进入 nextTick 队列 → 批量重渲染。

补充：真实的 Dep.target 其实是一个栈 （pushTarget / popTarget），用来处理嵌套收集——比如 render 里读一个 computed，会先压入 computed watcher 收集它内部的依赖，读完再弹出恢复成渲染 watcher。 这就是为什么「computed 依赖 data、render 又依赖 computed」不会串味。

Vue 3 核心实现代码 (手写最简版)

Vue 3 用 Proxy + Reflect 实现，核心是 track/trigger（依赖管理）、reactive （代理）、effect（副作用）。依赖关系存于 WeakMap<target, Map<key, Set<effect>>。

1. 全局依赖存储 & 当前活跃 effect
const targetMap = new WeakMap(); // target -> (key -> Set<effect>)
let activeEffect = null;         // 当前正在执行的副作用函数
2. track：get 时收集依赖
function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, (depsMap = new Map()));
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, (dep = new Set()));
  dep.add(activeEffect);        // 把当前 effect 收进依赖集合
}
3. trigger：set 时派发更新
function trigger(target, key) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;
  const dep = depsMap.get(key);
  if (dep) dep.forEach(effect => effect()); // 重新执行所有相关 effect
}
4. reactive：Proxy 代理整个对象（懒代理，无需递归初始化）
function reactive(target) {
  return new Proxy(target, {
    get(obj, key, receiver) {
      const res = Reflect.get(obj, key, receiver);
      track(obj, key);          // 读取时收集依赖
      return res;
    },
    set(obj, key, value, receiver) {
      const res = Reflect.set(obj, key, value, receiver);
      trigger(obj, key);        // 写入时派发更新
      return res;
    }
  });
}
5. effect：副作用函数
function effect(fn) {
  activeEffect = fn;
  fn();                         // 先执行一次，触发 get 完成收集
  activeEffect = null;
}
6. 跑起来看效果
const state = reactive({ count: 0 });
effect(() => console.log('count 变为', state.count)); // 收集依赖
state.count++;                  // 触发 set → trigger → effect 重新执行
// 输出：count 变为 0  （首次执行）
//       count 变为 1  （count++ 后重新执行）

Vue 3：核心组件 ↔ 组合式 API（Composition API）

上面那段核心代码里有四个「积木」：reactive()（Proxy 代理）、track/trigger （依赖收集 / 派发）、targetMap（全局依赖仓库）、effect() （副作用函数）。在真实 Vue 3 里，组合式 API 的每个函数都是这几个积木的「封装」。 effect 就是 Vue 2 里 Watcher 的等价物（真实类名 ReactiveEffect），activeEffect 等价于 Dep.target。

你写的 (Composition API) 底层对应 怎么起作用的
reactive(obj) reactive()（Proxy） 直接对应核心里的 reactive()：整个对象被 Proxy 代理（懒代理）； 读属性走 get → track，写属性走 set → trigger。
ref(0) / ref(obj) RefImpl（带 .value 拦截的响应式对象） 基本类型无法被 Proxy，所以 ref 用「一个对象 + .value 的 getter/setter 来调 track/trigger」实现单值响应式；模板里会自动解包 .value。
computed(() => ...) computed = ref + effect(lazy) + dirty 读 .value 时才懒执行 getter 并收集内部依赖；依赖变只把 dirty 置 true， 下次被读才重算并缓存。相当于 Vue 2 的「计算 Watcher」。
watchEffect(fn) 直接就是 effect(fn) 立即执行 fn 收集依赖，依赖变则重跑 fn。和你核心代码里的 effect() 几乎一模一样。
watch(src, cb) effect + scheduler + 回调 用 effect 跟踪 src，变化时通过 scheduler 调用你的回调 (newVal, oldVal)。相当于 Vue 2 的「用户 Watcher」。
<script setup> + 模板 渲染 ReactiveEffect <script setup> 只是声明响应式来源的语法糖；模板编译成的 render 函数本身就是一个 ReactiveEffect，读到的 ref/reactive 会被收集，数据变则重渲染。
shallowRef / shallowReactive / readonly 同一套 track/trigger 的变体 只是关闭深层代理或只读拦截，机制完全相同。
渲染 Effect（组件更新） 每个组件一个 ReactiveEffect，其 scheduler 把更新推入 job 队列， nextTick 时批量 flush（等价于 Vue 2 的异步更新队列）。
Computed = ref + 懒 effect + dirty 缓存： 没被读不求值的；被读且 dirty 才重算。
Watch / WatchEffect 用户侧 effect，配上 scheduler 决定刷新时机 （pre / post flush），变化后执行你的回调。

一个完整流程（以改 reactive 属性为例）：

1. reactive({ count: 0 }) → 返回 Proxy，读/写分别走 get/set 拦截。

2. 组件挂载 → 创建渲染 ReactiveEffect 并执行 render；render 读 state.count → get 拦截 → track(state, 'count') 把当前 activeEffect 收进 targetMap[state]['count'] 的 Set。

3. 改 state.count++ → set 拦截 → trigger(state, 'count') → 取出该 Set 里的 effect → 交给 scheduler 排队。

4. nextTick flush → 渲染 effect 重跑 → 视图更新。

补充两点差异（Vue 3 相对 Vue 2）：

① activeEffect 也是一个栈（effectStack），原理同 Vue 2 的 Dep.target 栈，用来处理 render 里读 computed 这类嵌套收集。

② trigger 还能感知「属性新增/删除」和「遍历（ITERATE_KEY）」—— 这是 Proxy 相比 Object.defineProperty 的天然优势，所以 Vue 3 不用 Vue.set。
