Vue 组件通信方式大全

父子 · 跨层级 · 兄弟 · 全局 —— 12 种通信方式原理、代码与选型（图文并茂）

一、总览：按「组件关系」分类

组件通信的本质是「数据往哪流、谁来触发」。面试时按组件关系组织答案最清晰：

  • 父子：props / emit / v-model / ref+expose
  • 爷孙（跨层级）：$attrs 透传 / provide + inject
  • 兄弟 / 任意组件：父组件中转 / mitt 事件总线 / Pinia 状态管理
  • 全局兜底：路由参数、window 事件、浏览器存储（非常规手段）

二、props：父 → 子（单向数据流）

props 是最基础的通信方式。核心原则是 单向数据流：父组件的数据「往下流」，子组件不能直接修改 prop，只能通过 emit 通知父组件来改——这样数据变化永远可追溯。

Vue 3 <script setup> 写法
<!-- 父组件 -->
<template>
  <Child :title="title" :list="list" @update:title="title = $event" />
</template>

<script setup>
import { ref } from 'vue'
import Child from './Child.vue'
const title = ref('默认标题')
const list = ref([1, 2, 3])
</script>
<!-- 子组件 Child.vue -->
<script setup>
// 运行时声明（推荐再配 TS 类型）
const props = defineProps({
  title: { type: String, default: '' },
  list:  { type: Array, required: true },
})
console.log(props.title)
</script>

<!-- 纯 TS 声明方式（更简洁） -->
<script setup lang="ts">
const props = defineProps<{
  title?: string
  list: number[]
}>()
</script>
WARNING props 是浅只读的：直接改 props.title 会警告；但如果传的是对象，改 props.obj.key 不会报错（改的是父组件里的原对象）—— 能跑但违反单向数据流，评审时会被打回，正确做法是 emit 出去让父组件改。

三、emit：子 → 父（自定义事件）

子组件通过 emit('事件名', 参数) 对外「喊话」，父组件用 @事件名 监听。defineEmits 同时起到声明文档 和校验作用。

Vue 3 写法
// 子组件
const emit = defineEmits(['change', 'submit'])
// 或 TS 写法：const emit = defineEmits<{ (e: 'change', val: number): void }>()

function onClick() {
  emit('change', 100) // 通知父组件，携带参数
}
<!-- 父组件监听 -->
<template>
  <Child @change="handleChange" />
</template>

<script setup>
function handleChange(val) {
  console.log('子组件传来的值：', val)
}
</script>
INFO · Vue2 vs Vue3 事件命名 Vue3 中组件事件不再有大小写自动转换的坑（DOM 模板限制）， 官方推荐事件名用 camelCase 声明、kebab-case 监听： emit('updateTitle') ↔ @update-title。

四、v-model：双向绑定的语法糖

v-model 本质就是 props + emit 的组合糖：

  • Vue3：v-model="x" 展开为 :modelValue="x" + @update:modelValue="x = $event"， 且支持多个 v-model（v-model:title、v-model:content）。
  • Vue2：展开为 :value + @input，一个组件只能有一个 v-model（额外同步要靠 .sync 修饰符，Vue3 中被 v-model:arg 取代）。

Vue3：自定义组件上使用 v-model
<!-- 父组件 -->
<template>
  <!-- 等价于 :modelValue="msg" @update:modelValue="msg = $event" -->
  <MyInput v-model="msg" v-model:title="pageTitle" />
</template>
// 子组件 MyInput.vue —— Vue3.4+ 推荐用 defineModel
const model = defineModel()          // 默认 v-model
const title = defineModel('title')   // v-model:title

function onInput(e) {
  model.value = e.target.value       // 赋值内部自动 emit
}
// 3.4 之前的等价手写版
const props = defineProps(['modelValue'])
const emit = defineEmits(['update:modelValue'])
function onInput(e) {
  emit('update:modelValue', e.target.value)
}

五、ref + defineExpose：父组件直接调用子组件

通过模板 ref 拿到子组件实例，可以直接调用其暴露的方法、 读取属性。 Vue3 中 <script setup> 默认是封闭的， 子组件必须用 defineExpose 显式暴露，父组件才能访问—— 这是与 Vue2（this.$refs.child.xxx 全开放）最大的区别。

Vue 3 写法
// 子组件
import { ref } from 'vue'
const count = ref(0)
function reset() {
  count.value = 0
}
defineExpose({ count, reset }) // 只暴露需要的部分
<!-- 父组件 -->
<template>
  <Child ref="childRef" />
  <button @click="childRef.reset()">重置子组件</button>
</template>

<script setup>
import { ref, onMounted } from 'vue'
const childRef = ref(null)
onMounted(() => {
  console.log(childRef.value.count) // 访问暴露的属性
})
</script>
WARNING 这种方式是命令式的，耦合度高，属于「逃生舱」： 适合表单组件的 focus() / validate()、 弹窗的 open() 等场景，不要拿它当常规数据通道。

六、$attrs：爷孙通信的轻量透传

$attrs 收集父组件传入的未被 props 声明的属性和事件。 在「包装组件」场景里，中间层组件可以 v-bind="$attrs" 一股脑透传给深层子组件， 实现爷 → 孙通信，而不用逐层声明 props。

Vue3 的变化：事件监听也进了 $attrs（Vue2 中事件和 class/style 是分开的），且 class/style 不再特殊，也可透传。

透传示例
<!-- 爷爷组件 -->
<template>
  <Wrapper :size="'large'" :color="'red'" @click="onClick" />
</template>
<!-- 中间层 Wrapper.vue：不声明 size/color，直接透传 -->
<template>
  <Deep v-bind="$attrs" />
</template>

<script setup>
// Vue3 setup 中用 useAttrs 拿到（非响应式读取用 attrs）
import { useAttrs } from 'vue'
const attrs = useAttrs()
</script>
<!-- 孙子 Deep.vue -->
<script setup>
const props = defineProps(['size', 'color']) // 消费掉需要的属性
</script>
TIP 设置 inheritAttrs: false（Vue3 写在 defineOptions({ inheritAttrs: false })）可以关闭「自动把 $attrs 挂到根元素」的行为，让你自己控制透传到哪个元素/组件。

七、provide / inject：跨层级注入

祖先组件 provide 数据，任意层级的后代组件 inject 使用，中间组件完全无感——解决「props 钻孔 （prop drilling）」问题。典型场景：主题色、国际化、当前登录用户、字典数据。

Vue 3 写法（传递 ref 保持响应式）
// 祖先组件
import { ref, provide } from 'vue'
const theme = ref('dark')
provide('theme', theme)              // 传 ref 本身，后代改 theme.value 全局生效
provide('theme', readonly(theme))    // 更严谨：只读注入，防止后代乱改
// 任意后代组件
import { inject } from 'vue'
const theme = inject('theme', 'light') // 第二个参数是默认值
WARNING provide 一个普通值（非 ref）时后代拿到的是死值， 祖先更新后代不更新。要响应式就传 ref / computed， 或直接 provide 一个带方法的对象（如 { theme, setTheme }），把修改权收敛回祖先—— 这也是组件库源码里最常见的模式。

八、作用域插槽：子组件把数据「递」给父组件

插槽通常被认为只是「内容分发」，但作用域插槽（scoped slot） 是一种真实的通信方式：子组件把内部数据作为参数传给插槽， 由父组件决定怎么渲染——数据流是「子 → 父」，渲染权是「父 → 子」。

典型场景：自定义列表项渲染
<!-- 子组件 List.vue：提供数据 -->
<template>
  <ul>
    <li v-for="item in items" :key="item.id">
      <!-- 把 item 传给插槽 -->
      <slot :item="item" :index="index">{{ item.name }}</slot>
    </li>
  </ul>
</template>
<!-- 父组件：拿到数据自定义渲染 -->
<template>
  <List :items="users">
    <template #default="{ item, index }">
      <span>{{ index }}. {{ item.name }}（VIP）</span>
    </template>
  </List>
</template>
INFO el-table 的 <template #default="{ row }"> 就是最常见的作用域插槽通信。默认插槽可简写 v-slot="props"；具名插槽用 #name="props"。

九、兄弟 / 任意组件：中转、mitt 事件总线

方案 A：共同父组件中转（推荐优先考虑）

兄弟 A emit 给父组件，父组件再通过 props 传给兄弟 B。 数据流清晰、可调试，层级浅时永远首选。

方案 B：mitt 事件总线（解耦通知）

Vue3 移除了实例上的 $on / $off / $once，官方推荐用 mitt 这样的微型事件库实现「发布-订阅」。适合无状态、一次性的事件通知 （如「退出登录」「全局 toast」），不适合传共享状态。

mitt 使用（npm i mitt）
// emitter.js —— 全局单例
import mitt from 'mitt'
export const emitter = mitt()
// 组件 A：发布事件
import { emitter } from './emitter'
function logout() {
  emitter.emit('user-logout', { reason: 'manual' })
}
// 组件 B：订阅 + 组件卸载时解绑（防内存泄漏）
import { onMounted, onUnmounted } from 'vue'
import { emitter } from './emitter'

const handler = (payload) => console.log('收到通知', payload)
onMounted(() => emitter.on('user-logout', handler))
onUnmounted(() => emitter.off('user-logout', handler))
WARNING · 事件总线三宗罪
  • 难追踪：事件在哪触发、谁在听，全靠全局搜索。
  • 易泄漏：忘记 off 会导致重复回调。
  • 无类型：Vue2 的 $emit 链路编辑器无法提示。
只做「通知」不做「状态」；能被 Pinia 解决的就不要上事件总线。

十、Pinia：全局状态管理（中大型项目首选）

当「共享状态」多起来（登录态、购物车、权限），props 总线和事件总线都会失控， 这时需要一个单一数据源（Store）： 所有组件都从 store 读数据、通过 action 改数据，变化集中、可调试、可持久化。 Vue3 官方推荐 Pinia（Vue2 可用 Vuex 3 / Pinia 2 均可）。

定义 Store
// stores/cart.js
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

export const useCartStore = defineStore('cart', () => {
  // state
  const items = ref([])
  // getter
  const totalPrice = computed(() =>
    items.value.reduce((s, it) => s + it.price * it.count, 0)
  )
  // action
  function addItem(item) {
    const exist = items.value.find((it) => it.id === item.id)
    exist ? exist.count++ : items.value.push({ ...item, count: 1 })
  }
  function clear() {
    items.value = []
  }
  return { items, totalPrice, addItem, clear }
})
任意组件中使用
import { useCartStore } from '@/stores/cart'
import { storeToRefs } from 'pinia'

const store = useCartStore()
const { items, totalPrice } = storeToRefs(store) // 解构保持响应式（只解 state/getter）

store.addItem({ id: 1, name: '键盘', price: 199 })
store.clear() // 任何组件调用，所有用到的组件同步更新
Pinia vs Vuex Pinia 没有 mutation（直接在 action 改）、天然支持 TS、支持多 store、 无嵌套模块、 devtools 完整支持，Vue 官方已把它定为默认方案。
storeToRefs 直接解构 store 会丢响应式；storeToRefs 只把 state/getter 转 ref（action 是函数，直接从 store 上取）。
适合放什么 跨页面/跨组件共享的状态。仅父子用的数据放 Pinia 反而增加复杂度—— 就近原则。

十一、其他非常规手段（了解即可）

手段 说明 风险 / 适用

window 挂载 / 自定义事件 window.dispatchEvent(new CustomEvent(...)) 能跨 iframe / 微前端，但脱离 Vue 体系难调试

十二、面试高频问答

Q1：Vue 组件通信方式有哪些？（高频必考）

按关系背：父子（props / emit / v-model / ref+defineExpose）→ 跨层级（$attrs 透传 / provide + inject）→ 兄弟（父组件中转 / mitt）→ 全局（Pinia / Vuex）→ 兜底（路由参数、storage）。每种都能说清「方向 + 场景」即可拿高分。

Q2：v-model 的原理？Vue2 和 Vue3 有什么区别？

本质是语法糖：Vue2 = :value + @input（单 v-model，多值用 .sync）； Vue3 = :modelValue + @update:modelValue， 支持多个 v-model 参数（v-model:title）， 3.4 起子组件用 defineModel 一行搞定。

Q3：provide/inject 的响应式怎么保证？

provide 一个 ref / reactive / computed 对象（而不是值本身）， 后代读取/修改其 .value 即保持响应式；若要防止后代乱改， 用 readonly() 包一层再 provide，同时 provide 一个 setXxx 方法收敛修改入口。

Q4：事件总线有什么问题？为什么 Vue3 移除了 $on？

发布订阅让数据流不可追踪、容易忘记解绑导致重复触发、 事件名无类型约束。Vue3 移除实例方法后，官方引导： 状态共享用 Pinia，事件通知用 mitt 等显式库，且记得在 onUnmounted 中 off。

Q5：props 传对象后子组件改它的属性会怎样？

props 本身浅只读：改 props.obj.key 不会报警告 （因为改的是父组件里那个原对象），且父组件也会跟着变——但这属于 隐式双向修改，破坏单向数据流，排查困难。正确姿势： emit 事件让父组件改，或用 v-model / defineModel 显式约定。

十三、选型指南 & 记忆口诀

父子 → props + emit 默认答案。表单组件加 v-model；要调子组件方法才用 ref + defineExpose。
跨层级 → provide / inject 主题、用户、字典这类「全局但轻」的数据；包装组件用 $attrs 透传。
兄弟 → 父中转优先 层级浅用父组件中转；解耦通知用 mitt（记得解绑）。
全局共享 → Pinia 多页面共享状态、需要 devtools 调试和持久化时上 store。
记忆口诀 「父子 props 事件传，双向 v-model 糖两半；跨层 provide 加 inject， 透传 $attrs 少声明；兄弟中转或 mitt，全局状态 Pinia 管」。
