Vue：computed 与 watch 详细对比

缓存机制 · 底层原理 · 使用方式 · 面试高频坑点（图文并茂）

一、一句话区别 & 总览对比

computed 是「带缓存的派生值」——由已有响应式数据 计算出新值，依赖不变就复用缓存，模板里像普通变量一样用。

watch 是「数据变化的监听器」——当被监听的数据变化时， 执行一段副作用逻辑（发请求、操作 DOM、写日志等），它关注的是「做某件事」。

记住核心差异：computed 问「值是多少」，watch 问「数据变了我要干什么」。

对比维度 computed watch
定位 派生 / 计算出一个新值（声明式） 监听数据变化并执行副作用（命令式）
返回值 有，必须 return 一个值 无（回调函数没有返回值的意义）
缓存 有缓存：依赖不变时多次访问只算一次 无缓存：数据一变回调就执行
是否立即执行 首次访问时同步求值（lazy 惰性） 默认不执行，immediate: true 时立即执行一次
新旧值 不提供新旧值 回调提供 (newVal, oldVal)
异步操作 不适合（getter 应是纯同步函数） 适合：防抖、发请求、定时器
模板中的使用 {{ double }} 像变量一样 不直接在模板使用
典型场景 过滤列表、总价计算、格式化拼接 路由变化、表单联动、异步请求、深度监听
TIP 官方建议：能被已有状态推导出来的，一律用 computed； 只有「变化时需要执行副作用」的场景才用 watch。 大量 watch 往往是代码坏味道——很可能本该写成 computed。

二、computed 原理：缓存是怎么实现的？

computed 底层是一个 lazy（惰性）的副作用函数（effect）：

  • 创建时不立即执行 getter，而是生成一个带 dirty 标记的 ComputedRefImpl。
  • 首次读取 .value 时 dirty === true，才执行 getter， 并收集 getter 里用到的响应式依赖。
  • 依赖变化时不马上重算，只把 dirty 置回 true（触发 triggerRefValue 通知订阅者）。
  • 下次再读取时发现 dirty === true 才重算，否则直接返回缓存值。

这就是「依赖不变 → 直接吃缓存」的来源，也是它和 methods 最大的区别。

lazy 惰性求值 创建时不执行，第一次被读取才执行。若组件根本没用到某个 computed，getter 永远不会跑。
dirty 缓存标记 dirty 是「脏位」：依赖变了只标记脏，不重算； 真正被读取时才按需重算——这就是缓存的本质。
本身就是 ref computed 返回一个只读的 ComputedRef，同样有 .value，同样能被其它 computed / 渲染函数依赖，形成依赖链。
WARNING · 两个经典坑
  • getter 里不要写异步逻辑（setTimeout / await），computed 要求同步返回，异步结果无法被响应式追踪。
  • getter 必须是纯函数：不要在里面修改其它状态或发请求。 「在 computed 里改数据」会导致循环更新警告 “Maximum recursive updates exceeded”。
缓存效果验证：computed vs methods
import { ref, computed } from 'vue'

const count = ref(0)
let computedLogCount = 0
let methodLogCount = 0

const double = computed(() => {
  computedLogCount++        // 只有依赖变化后【再次被读取】时才会 +1
  return count.value * 2
})

function getDouble() {
  methodLogCount++          // 每次调用都执行，无缓存
  return count.value * 2
}

double.value // 执行 1 次 getter
double.value // 命中缓存，不再执行 ❗
double.value // 还是缓存 → computedLogCount === 1

count.value = 10   // 依赖变了，这里只是把 dirty 标记为 true，并不重算
double.value // 此时才重算 → computedLogCount === 2

三、watch 原理：监听是怎么触发的？

watch 底层同样是 effect，但和 computed 不同：

  • 它会立即执行一次getter（内部为 traverse）， 目的仅仅是收集依赖，拿到结果后丢弃。
  • 依赖变化时，通过 scheduler（调度器） 把回调放进 job 队列，以 flush 指定的时机执行 （pre 组件更新前 / post 更新后 / sync 同步）。
  • 回调执行时把新值、旧值传给你。

一句话：computed 是「被读取才重算」，watch 是「变化了就主动跑回调」。

INFO · 为什么直接 watch reactive 对象深层属性要小心？ 给 watch 传一个 reactive 对象时会自动开启 deep: true；但传一个 getter 函数（如 () => state.obj.key）时默认不深度—— 只有 key 本身被替换才触发，内部嵌套变化不会。需要深度时显式加 { deep: true } 或让 getter 返回解构后的值。
traverse 收集深层依赖 内部通过递归遍历对象所有属性来建立深度依赖，所以 deep: true 在大对象上有性能开销，能精确监听就别开 deep。
flush 控制时机 默认 pre：回调在组件更新前跑，里面拿到的还是旧 DOM； 需要「等 DOM 更新完」用 flush: 'post'（等价 watchPostEffect）。
副作用清理 onCleanup 回调第三个参数 onCleanup(fn)：注册的函数会在 下次回调执行前 / watcher 停止时调用——用于取消上一次未完成的请求、清定时器。

四、基本用法对比（Composition API）

computed：派生值
import { ref, computed } from 'vue'

const price = ref(100)
const quantity = ref(2)

// 可写（推荐）：getter 形式
const total = computed(() => price.value * quantity.value)

// 完整形式：可写 computed（少见，双向派生时用）
const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: (val) => {
    ;[firstName.value, lastName.value] = val.split(' ')
  },
})
watch：监听多种数据源
import { ref, reactive, watch } from 'vue'

const count = ref(0)
const state = reactive({ name: 'vue' })

// 1) 单个 ref
watch(count, (n, o) => console.log(n, o))

// 2) getter 函数（精确监听某个属性）
watch(() => state.name, (n, o) => console.log(n, o))

// 3) reactive 对象（自动 deep: true）
watch(state, (n) => console.log(n))

// 4) 多个源 → 回调收到数组形式的新旧值
watch([count, () => state.name], ([nc, nn], [oc, on]) => {
  console.log(nc, nn, oc, on)
})
watch 的四个常用选项
watch(
  () => state.list,
  (newList) => {
    console.log('list 变了', newList)
  },
  {
    immediate: true, // 创建时立即执行一次回调（拿初始值做初始化很常用）
    deep: true,      // 深度监听（getter 形式默认不深度；reactive 源自动为 true）
    flush: 'post',   // 'pre'（默认，更新前）| 'post'（更新后，可拿 DOM）| 'sync'（同步）
    once: true,      // 3.4+：只触发一次后自动停止
  }
)
停止监听 & 副作用清理
// watch 在 setup / <script setup> 中创建时，组件卸载会自动停止；
// 异步回调中创建（如 setTimeout 里）则必须手动停止！
const stop = watch(count, (n) => console.log(n))
stop() // 手动停止

// onCleanup：处理竞态（搜索输入的经典场景）
watch(keyword, async (val, old, onCleanup) => {
  const controller = new AbortController()
  onCleanup(() => controller.abort()) // 新请求发出前，中止上一次
  const res = await fetch(`/api/search?q=${val}`, { signal: controller.signal })
})

五、补充：watchEffect —— watch 的「自动依赖」兄弟

watchEffect 不用声明监听谁——它立即执行一次回调， 回调里用到哪些响应式数据，就自动监听哪些。适合「多个状态、同一段逻辑」的场景。

特性 watch watchEffect
依赖来源 显式指定 source 回调执行过程中自动收集
立即执行 默认不执行（immediate 可选） 总是立即执行一次
新旧值 提供 (newVal, oldVal) 不提供
惰性 依赖变化才跑回调 创建时就跑一次（适合初始化副作用）
适用 明确知道监听谁、需要旧值、需要惰性 多个依赖触发同一段逻辑、且需要首次就执行
watchEffect 示例
import { ref, watchEffect } from 'vue'

const keyword = ref('')
const page = ref(1)

// keyword 或 page 任一变化都会重新请求；创建时也立即请求一次
watchEffect(async () => {
  const res = await fetch(`/api/list?kw=${keyword.value}&page=${page.value}`)
})

六、面试高频问答

Q1：computed 和 methods 的区别？

computed 有缓存：依赖不变时反复访问只算一次；methods 每次调用都重新执行。渲染场景下若模板中多处使用同一派生值， computed 只算一次，methods 会执行多次。

Q2：computed 和 watch 的区别？该怎么选？

  • computed：由数据算出一个值，有缓存、必须同步、不能做副作用。适合：求和、过滤、格式化。
  • watch：数据变化时执行副作用，无缓存、可异步、有新旧值。适合：请求接口、操作 DOM、路由监听。
  • 判断标准：如果这段逻辑最终是为了得到一个值 → computed； 如果是为了做一件事 → watch。

Q3：为什么 computed 里不能写异步？

getter 必须同步返回结果——依赖收集和缓存机制都建立在同步求值上。 异步结果返回时早已脱离本次求值流程，无法写回缓存，模板也拿不到。 需要「异步派生值」应该用 watch + ref（或 watchEffect）， 把结果存进一个普通 ref。

Q4：watch 监听 reactive 对象的属性没触发？

三种正确姿势：
  1. getter：watch(() => state.obj, cb, { deep: true })
  2. getter 返回具体值：watch(() => state.obj.key, cb)
  3. 整个对象：watch(state.obj, cb)（自动深度）
注意：watch(() => state.obj, cb) 不加 deep 时， 只有 state.obj 被整体替换才触发，内部属性变化不触发。

Q5：computed 的缓存什么时候失效？

依赖的响应式数据发生变化时只是「标记脏」（dirty = true）， 并不立刻重算；等下一次被读取时才真正重新执行 getter 并更新缓存。 这种「按需重算」避免了依赖高频变化但没人读取时的无效计算。

七、最佳实践 & 记忆口诀

能用 computed 就别用 watch 「a 变了就去改 b」这种代码十有八九应该写成 b = computed(() => f(a))，声明式更不易出 bug。
computed 保持纯 & 同步 getter 里不修改状态、不发请求、不写异步；需要异步结果就用 watch/watchEffect + ref 存结果。
watch 记得清理副作用 异步请求 / 定时器用 onCleanup 清理，防止竞态和内存泄漏； 组件外（异步中）创建的 watcher 手动 stop()。
deep 慎用 大对象深度监听开销大；优先用精确的 getter 监听具体属性。
记忆口诀 「算值用 computed（有缓存、要同步），干活用 watch（能异步、有新旧）； 一堆依赖一段逻辑，watchEffect 一把梭」。
综合示例：购物车（三者各司其职）
import { ref, computed, watch, watchEffect } from 'vue'

const items = ref([
  { name: '键盘', price: 199, count: 1 },
  { name: '鼠标', price: 99, count: 2 },
])

// 1) 派生值 → computed（自动跟随 items，有缓存）
const total = computed(() =>
  items.value.reduce((sum, it) => sum + it.price * it.count, 0)
)

// 2) 值变化要做「一件事」（上报埋点）→ watch
watch(total, (n, o) => {
  console.log(`总价从 ${o} 变为 ${n}`)
  analytics.report('cart_total_change', { from: o, to: n })
})

// 3) 多依赖同一逻辑 + 需要立即执行一次 → watchEffect
const keyword = ref('')
watchEffect(() => {
  document.title = `购物车(${items.value.length}) - ${keyword.value || '全部商品'}`
})
