Vue 3：ref 与 reactive 详细对比

原理结构 · 解包规则 · 响应式丢失的坑 · 最佳实践（图文并茂）

一、一句话区别 & 总览对比

ref 是一个「响应式盒子」——它把任何值（基本类型或对象）包进 { value: ... } 里，靠这个对象的 value 属性做 track/trigger。

reactive 是「响应式代理」——它直接对对象/数组本身 用 Proxy 包装，对象的每个属性读写都被拦截。

记住核心差异：ref 包的是「值」，reactive 包的是「对象」。

对比维度 ref reactive
本质 包装对象（盒子）{ value }，带 __v_isRef 标记 原始对象的 Proxy 代理
能包裹的类型 任意：基本类型 + 对象/数组 仅对象 / 数组（基本类型会报警告）
访问 / 修改方式 需 .value（模板顶层自动解包） 直接 .属性
对象内部是否深层响应式 是（对象的 value 内部自动调 reactive()） 是（深层递归代理）
解构 / 展开 安全：拿到的仍是 ref 对象 丢失：拿到的是原始值，脱钩
整体重新赋值 可以：ref.value = 新对象 不行：会断开响应式引用
TS 类型 Ref<T> UnwrapNestedRefs<T>

二、原理剖析：为什么 ref 能包基本类型？

Proxy 只能代理「对象」，没法代理一个数字 0。所以 Vue 3 用 ref 套一层对象 来曲线救国：把基本类型塞进 { value }，再对这个对象的 value 做响应式。而对对象类型的 ref，它的 value 内部又会调用 reactive()，所以行为一致。

ref 的「拆箱」 源码里 ref 走 RefImpl 类：get value() 调 track，set value() 调 trigger。模板和 reactive 属性会自动「拆箱」成原始值。
reactive 的代理 源码里 reactive 走 Proxy + track/trigger， 并对嵌套对象懒代理（访问到才代理），深层天然响应式。
两者底层同源 ref 的对象分支和 reactive 最终都落到同一套 track / trigger / targetMap 机制上，所以「响应式的本质」完全一样。

三、使用方式对比

1. JS 中的基本用法
import { ref, reactive } from 'vue'

// ref：任意类型都行，访问 / 修改都要 .value
const count = ref(0)
console.log(count.value) // 0
count.value++            // 修改

// reactive：只能用于对象 / 数组，直接访问属性
const state = reactive({ count: 0 })
console.log(state.count) // 0
state.count++
2. 在 <script setup> + 模板中的区别
<script setup>
import { ref, reactive } from 'vue'
const count = ref(0)
const state = reactive({ count: 0 })
</script>

<template>
  <!-- ref 在模板顶层自动解包，不用写 .value -->
  <p>{{ count }}</p>
  <!-- reactive 直接写属性 -->
  <p>{{ state.count }}</p>
</template>
INFO 模板顶层 ref 会自动解包，这是编译期的语法糖；在 return 给模板时 Vue 已经帮你处理了，但在 JS 逻辑里永远要写 .value。

四、ref 的自动解包（unwrapping）规则

「解包」指 ref 在某种上下文里被自动当成它的 .value 来用。 规则很简单：只有在「模板顶层」或「作为 reactive 对象的属性」时才会自动解包， 其它情况（普通对象、数组、Map）都不会解包，需要手动 .value。 

graph TD
    Start["一个 ref 出现在哪里?"] --> Q1{"在 模板顶层 ?"}
    Q1 -->|是| A1["自动解包<br/>直接写 count，不用 .value ✅"]
    Q1 -->|否| Q2{"是 reactive 对象的属性 ?"}
    Q2 -->|是| A2["自动解包<br/>state.count 无需 .value ✅"]
    Q2 -->|否| Q3{"在 数组 / Map / 普通对象 中 ?"}
    Q3 -->|是| A3["不解包<br/>需手动 .value ⚠️"]
    Q3 -->|否| A4["独立使用<br/>需 .value"]
解包规则代码验证
import { ref, reactive } from 'vue'

const count = ref(0)

// 1) 作为 reactive 对象的属性 → 自动解包
const state = reactive({ count }) // state.count 已经是数字 0（ref 被拆箱）
console.log(state.count)          // 0（无需 .value）
state.count++                     // 等价于 count.value++

// 2) 在普通对象 / 数组 / Map 中 → 不解包，需手动 .value
const plain = { count }           // plain.count 仍是 ref 对象
console.log(plain.count.value)    // 0

const list = reactive([count])    // ⚠️ 数组里不会自动解包
console.log(list[0].value)        // 0（仍需 .value）

五、最易踩的坑：响应式丢失

这是 ref 和 reactive 体验差异最大的地方。 reactive 一旦被解构 / 展开，拿到的是「原始值」，响应式当场断掉； 而 ref 解构后拿到的仍是 ref 对象，.value 永远有效。 

graph TD
    subgraph Bad["reactive 的坑"]
        B1["const state = reactive({count:0})"] --> B2["const { count } = state"]
        B2 --> B3["count 是普通数字<br/>与 state 脱钩 ❌"]
        B1 --> B4["state = {count:1}"]
        B4 --> B5["state 不再是代理<br/>响应式断裂 ❌"]
    end
    subgraph Good["ref 的优势"]
        G1["const count = ref(0)"] --> G2["const { count } = obj<br/>（仍是 ref 对象）"]
        G2 --> G3["count.value 永远 track ✅"]
        G1 --> G4["count.value = {x:1}"]
        G4 --> G5["整体替换没问题 ✅"]
    end
reactive 解构 → 丢失响应式 ❌
import { reactive } from 'vue'

const state = reactive({ count: 0, name: 'vue' })
const { count } = state     // count 变成普通数字，与 state 脱钩
count++                     // ❌ 不会触发任何更新
ref 解构 → 不丢失 ✅
import { ref } from 'vue'

const countRef = ref(0)
const obj = { countRef }
const { countRef: c } = obj  // c 还是 ref 对象
c.value++                    // ✅ 仍然响应式
用 toRefs / toRef 拯救 reactive 解构 ✅
import { reactive, toRefs, toRef } from 'vue'

const state = reactive({ count: 0, name: 'vue' })
const { count, name } = toRefs(state) // 全变成 ref，解构不丢失
count.value++

const nameRef = toRef(state, 'name')   // 只取单个属性为 ref
nameRef.value = 'vue3'
WARNING toRefs 只对已存在的属性有效；若解构了一个后续可能新增的属性， 应用 toRef。另外 toRefs 返回的每个 ref 与源对象保持同步， 改一方另一方也变。

六、整体重新赋值的差异

reactive 的响应式绑定在「那个具体的代理对象」上。如果你把变量指向一个新对象， 新对象没有被代理，响应式直接断裂。而 ref 只是改了盒子里的 .value，盒子本身不变，所以整体替换完全没问题。

对比代码
// ❌ reactive 不能整体替换（会断掉响应式引用）
let state = reactive({ count: 0 })
state = { count: 1 }        // state 不再是响应式代理 ❌

// ✅ ref 可以整体替换 value
const stateRef = ref({ count: 0 })
stateRef.value = { count: 1 } // 完全没问题 ✅（新对象也会被 reactive 化）
TIP 如果你确实需要「整体换对象」又想用类似 reactive 的写法，可以包一层： const state = reactive({ data: {...} })，之后用 state.data = 新对象 替换，响应式不丢。或者直接用 ref。

七、到底该用哪个？（最佳实践）

基本类型 → ref 数字、字符串、布尔值只能用 ref，reactive 不接受基本类型。
对象 / 表单状态 → reactive 表单、配置对象用 reactive 更直观，访问不用到处写 .value。
组合式函数返回值 → ref composables 返回 ref 最安全：调用方能解构、不会丢失响应式、类型一致。

官方 / 社区的主流建议：

  • 优先用 ref：更一致、对 TypeScript 更友好、避免解构 / 重赋值丢失。
  • 当你有一组强耦合、几乎不解构、不需要整体替换的对象属性时， 用 reactive 更顺手（如 const form = reactive({...})）。
  • 需要解构 reactive 对象时，记得用 toRefs / toRef。
  • 深层只想浅层响应式时，可用 shallowRef / shallowReactive； 只读场景用 readonly。
记忆口诀 「值用 ref（盒子装值），对象用 reactive（代理对象）；要解构、要整换，统统用 ref」。

八、一个完整可跑的对比示例

推荐写法：组合式函数返回 ref
import { ref, reactive, computed, toRefs } from 'vue'

// 1) 基本类型用 ref
const count = ref(0)

// 2) 表单对象用 reactive（不解构时很爽）
const form = reactive({ name: '', age: 0 })

// 3) 计算属性
const double = computed(() => count.value * 2)

// 4) composable 返回 ref，调用方可安全解构
function useCounter() {
  const n = ref(0)
  const inc = () => n.value++
  return { n, inc } // 解构不丢失 ✅
}
const { n, inc } = useCounter()

// 5) 若必须解构 reactive，用 toRefs
const { name, age } = toRefs(form)
模板（ref 自动解包）
<template>
  <p>count: {{ count }}</p>
  <p>double: {{ double }}</p>
  <p>name: {{ form.name }}</p>
  <button @click="inc">+1</button>
</template>
