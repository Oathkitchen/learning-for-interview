Vue 插槽、自定义指令、异步组件

三种「组件扩展机制」：内容分发 · DOM 能力复用 · 按需加载（图文并茂）

〇、总览：它们分别解决什么问题？

机制 一句话定位 典型场景
插槽 Slot 内容分发：父组件往子组件的「预留位置」塞模板， 且渲染逻辑（变量）归父组件管 弹窗内容、列表项自定义渲染、布局组件
自定义指令 DOM 能力复用：把「直接操作 DOM 的逻辑」封装成可复用的 v-xxx 自动聚焦、图片懒加载、按钮权限控制
异步组件 按需加载：组件代码拆成独立 chunk，用到时才下载 路由懒加载、重组件（图表/富文本）延迟加载
记忆定位 插槽是「内容层面」的扩展，指令是「DOM 行为层面」的扩展， 异步组件是「加载时机层面」的优化——三者共同点都是组件复用的增强手段。

一、插槽（Slot）：内容分发

1.1 三种插槽

插槽本质：子组件用 <slot> 挖「坑」，父组件往坑里填内容； 填的内容在父组件作用域编译（能用父组件的数据），但渲染位置在子组件。

  • 默认插槽：<slot>，只有一个不具名出口。
  • 具名插槽：<slot name="header">，父组件用 #header 填。
  • 作用域插槽：子组件把内部数据通过 slot props 「递」给父组件的插槽内容使用。

三种插槽的完整用法
<!-- 子组件 BaseLayout.vue：定义出口 -->
<template>
  <header>
    <slot name="header">默认标题</slot>  <!-- 具名出口，含后备内容 -->
  </header>
  <main>
    <slot>没有传内容时显示我</slot>       <!-- 默认出口 -->
  </main>
  <footer>
    <slot name="footer" :year="2026"></slot>
  </footer>
</template>
<!-- 父组件：填坑 -->
<template>
  <BaseLayout>
    <!-- 具名插槽：template + #name（v-slot:name 的缩写） -->
    <template #header>
      <h1>{{ pageTitle }}</h1>  <!-- ✅ 用的是【父组件】的数据 -->
    </template>

    <!-- 默认插槽：内容直接写（省略 template #default） -->
    <p>主体内容</p>

    <!-- 作用域插槽：解构子组件传来的 slot props -->
    <template #footer="{ year }">
      <span>© {{ year }} my-app</span>
    </template>
  </BaseLayout>
</template>
作用域插槽的经典场景：子组件给数据，父组件管渲染
<!-- 子组件 List.vue -->
<template>
  <ul>
    <li v-for="(item, index) in items" :key="item.id">
      <slot :item="item" :index="index">{{ item.name }}</slot>
    </li>
  </ul>
</template>
<!-- 父组件 -->
<template>
  <List :items="users">
    <template #default="{ item, index }">
      <!-- el-table 的 { row } 就是这个机制 -->
      <b>{{ index + 1 }}.</b> {{ item.name }}
    </template>
  </List>
</template>
编译作用域规则 插槽内容在父组件作用域编译：里面只能用父组件的数据； 子组件的数据必须显式通过 slot props 传出来，不能直接引用。
动态插槽名 v-slot:[dynamicSlotName]，与动态指令参数同规则 （模板内表达式小写）。
Vue2 → Vue3 语法变化 Vue2 的 slot="header" + slot-scope 已废弃， Vue2.6+ / Vue3 统一为 v-slot（#），且 v-slot 只能写在 <template> 上（默认插槽可写在组件标签上）。
INFO · 插槽的底层原理（面试加分） 编译后，插槽内容会变成 返回 vnode 的函数，挂在子组件 vnode 的 children 对象上（如 { header: () => h(...), default: (props) => h(...) }）。 子组件渲染 <slot> 时就是调用对应函数—— 作用域插槽传数据，就是把这个函数以子组件数据为参数调用。 这也解释了「插槽内容是惰性的：父组件数据变了才重新执行插槽函数」。

二、自定义指令：封装 DOM 操作

2.1 什么时候用指令？

判断标准：这段逻辑只关心 DOM 元素本身（聚焦、监听滚动、进入视口）， 不产生状态、不参与模板逻辑 → 封装成指令； 如果需要返回数据给模板用（如 IntersectionObserver 的结果要显示）→ 封装成组合式函数更合适。

钩子 时机 典型用途
created 元素属性初始化前 读取静态属性、事件预绑定
beforeMount 插入 DOM 前 最后的机会修改元素属性
mounted 元素插入 DOM 后 focus()、addEventListener、observer.observe
beforeUpdate / updated 绑定值变化前后 对比 binding.oldValue 做增量处理
beforeUnmount / unmounted 元素卸载前 / 后 removeEventListener、disconnect（必做）
钩子参数详解（binding 对象）
app.directive('demo', {
  mounted(el, binding, vnode) {
    // el       : 指令绑定的真实 DOM 元素
    // binding  : {
    //   value     : v-demo="1 + 1" → 2（表达式求值结果）
    //   oldValue  : 上一次的 value（仅在 beforeUpdate/updated 中可用）
    //   arg       : v-demo:foo → 'foo'
    //   modifiers : v-demo.foo.bar → { foo: true, bar: true }
    //   instance  : 使用该指令的组件实例
    // }
    // vnode    : 元素对应的 vnode
  },
})

2.3 实战：三个最常用的自定义指令

① v-focus 自动聚焦
// 全局注册：app.directive('focus', ...)
const vFocus = {
  mounted: (el) => el.focus(), // 元素上直接写 v-focus 即可（setup 内局部指令）
}
// <script setup> 里命名规则：变量必须叫 vXxx，模板用 v-xxx
② v-lazy 图片懒加载
const lazyMap = new WeakMap() // 元素 → observer，防重复创建

export default {
  mounted(el, binding) {
    el.src = '占位图.png' // 先用占位图
    const io = new IntersectionObserver((entries) => {
      if (entries[0].isIntersecting) {
        el.src = binding.value // 进入视口才加载真实地址
        io.unobserve(el)
      }
    })
    io.observe(el)
    lazyMap.set(el, io)
  },
  updated(el, binding) {
    if (binding.value !== binding.oldValue) el.src = binding.value
  },
  unmounted(el) {
    lazyMap.get(el)?.disconnect() // 必须清理
  },
}
// 用法：<img v-lazy="item.cover" />
③ v-permission 按钮权限
import { useUserStore } from '@/stores/user'

export default {
  mounted(el, binding) {
    const { roles } = useUserStore()
    // v-permission="['admin']"：无权限直接移除元素
    if (!binding.value.some((r) => roles.includes(r))) {
      el.parentNode?.removeChild(el)
    }
  },
}
// 用法：<button v-permission="['admin']">删除</button>
简写形式与函数式指令
// 1) 对象字面量简写：mounted + updated 用同一个函数
const vColor = (el, binding) => {
  el.style.color = binding.value
}

// 2) 带修饰符的解析：v-loading.fullscreen="show"
function mounted(el, binding) {
  if (binding.modifiers.fullscreen) {
    /* 全屏遮罩逻辑 */
  }
}

// 3) 传对象字面量：v-pos="{ x: 10, y: 20 }"
function mounted(el, binding) {
  el.style.transform = `translate(${binding.value.x}px, ${binding.value.y}px)`
}
WARNING · 两条铁律
  • mounted 里加的监听 / observer，必须在 unmounted 里清理，否则内存泄漏 + 重复回调。
  • 指令只在真实 DOM 上工作：组件上使用指令时（极少） 拿到的是组件根元素，且 Vue3 已移除组件级指令的隐式透传，慎用。
INFO · Vue2 → Vue3 钩子改名对照 bind → mounted、inserted → beforeMount 附近、 update / componentUpdated → beforeUpdate / updated、 unbind → unmounted，并新增 created / beforeUnmount， 与组件生命周期完全对齐。

三、异步组件：按需加载

defineAsyncComponent 把组件定义包装成「用到时才去加载」： 底层基于动态 import()，构建时该组件会被拆成 独立 chunk，首次渲染到它时才发起网络请求下载并渲染。

基础用法
import { defineAsyncComponent } from 'vue'

// 简写：工厂函数返回 Promise
const HeavyChart = defineAsyncComponent(() =>
  import('./components/HeavyChart.vue')
)

// 完整选项：loading / error / delay / timeout
const HeavyEditor = defineAsyncComponent({
  loader: () => import('./components/HeavyEditor.vue'),
  loadingComponent: Spinner,       // 加载中组件
  errorComponent: ErrorBox,        // 加载失败组件
  delay: 200,    // 默认 200ms：网络快时不闪 loading
  timeout: 10000, // 超时判定为失败（可配 retry）
  onError(err, retry, fail, attempts) {
    if (attempts <= 3) retry() // 失败自动重试 3 次
    else fail()
  },
})
配合 Suspense（实验性）统一处理异步边界
<template>
  <Suspense>
    <AsyncPage />  <!-- 内部有异步 setup 的组件 -->
    <template #fallback>
      <Skeleton />  <!-- 等待时的占位 -->
    </template>
  </Suspense>
</template>

对比 defineAsyncComponent Suspense
作用层次 单个组件级别的按需加载 子树级别的异步协调（多个异步组件统一 fallback）
触发方式 渲染到该组件时才 import 组件 setup 含顶层 await 即视为异步
状态 稳定，生产可用 仍为实验性，API 可能变化
典型搭配 重组件、弹窗内容 整页级加载骨架屏
路由懒加载的本质 component: () => import('...') 就是把「异步组件工厂」交给 vue-router，进入路由时才加载 chunk——同一个机制。
弹窗 + 异步组件组合 弹窗内容用异步组件 + v-if 控制：不打开就不下载代码， 首屏体积明显减小。
delay 的意义 默认 200ms 内加载完成就不显示 loading， 防止快速网络下 loading 闪烁（layout shift）。
TIP · Vue2 写法差异 Vue2 中是 components: { Comp: () => import('...') }， 高级选项传对象 { component, loading, error, delay, timeout }； Vue3 统一收敛到 defineAsyncComponent。

四、面试高频问答

Q1：插槽的作用？作用域插槽解决了什么问题？

插槽实现内容分发，让组件的「结构」可定制。 普通插槽只能用父组件的数据（编译作用域）； 作用域插槽让子组件把内部数据作为参数传回插槽函数， 实现「数据归子组件、渲染归父组件」——列表、表格组件自定义单元格的基础。

Q2：插槽在编译后是什么？（原理）

插槽内容编译成返回 vnode 的函数，挂在子组件 vnode 的 children 上。子组件渲染 <slot> 出口时调用对应函数； 作用域插槽就是把子组件数据作为函数参数传入。 默认插槽内容惰性求值——父组件依赖变化时才重新执行生成新 vnode。

Q3：自定义指令有哪些钩子？和组件生命周期的关系？

Vue3 共 7 个：created / beforeMount / mounted / beforeUpdate / updated / beforeUnmount / unmounted，与组件生命周期一一对齐。 最常用的是 mounted（绑定 DOM 能力）和 unmounted（清理监听）。参数核心是 binding：value / oldValue / arg / modifiers / instance。

Q4：异步组件的原理？defineAsyncComponent 各选项含义？

基于动态 import() + Promise 状态机：渲染时调用 loader 拿到 Promise， pending 期间超过 delay 显示 loading，resolve 后渲染目标组件并缓存， reject 或超过 timeout 显示 errorComponent（支持 retry() 重试）。 构建层面由打包器把目标组件拆成独立 chunk，实现按需加载。

Q5：路由懒加载和异步组件什么关系？

路由懒加载 component: () => import('...') 的值正是一个 异步组件工厂函数——vue-router 内部就是用异步组件机制实现的。 区别只在触发时机：路由懒加载在导航确认时加载， 组件级异步在渲染到该组件时加载。

五、最佳实践 & 记忆口诀

插槽：出口给后备内容 <slot> 里写默认内容，防止父组件没传时空白； 作用域插槽 props 尽量解构 + 命名清晰（{ item, index }）。
指令：加监听必清理 mounted 里注册的 listener / observer 必须在 unmounted 移除； 只操作 DOM 不产状态，需要状态就用组合式函数。
异步组件：用在刀刃上 重组件（图表/编辑器/大表格）与弹窗内容做按需加载； delay 200ms 防闪烁，error 组件给 retry。
弹窗 + v-if + 异步 打开才挂载 + 才下载 chunk，首屏体积最小化。
记忆口诀 「插槽挖坑填内容（数据子传父渲染），指令挂 DOM 封行为（加监听必清理）， 异步组件 import()（delay 防闪错重试）」。
